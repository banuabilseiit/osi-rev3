# ИИ-ревизор ОСИ

Приложение помогает проверить отчёты объединения собственников имущества
(ОСИ, Казахстан): читает отчёты (PDF с текстом, сканы, фото), проверяет
арифметику и остатки, находит необычные расходы, **задаёт уточняющие вопросы**
(«загрузите чек по такому-то расходу») и выдаёт итоговый отчёт.

> Индивидуальный проект курса AI Capstone. Тема: интеграция CV + NLP + ML.

## Как это работает

```
Загрузка файлов ─► CV: выпрямление скана, поиск линий таблицы
                 ─► OCR (EasyOCR ru+en) / текстовый слой PDF
                 ─► восстановление таблицы: строки, колонки, коды пунктов
                 ─► NLP: роли строк (нечёткое сопоставление), контрагенты,
                         классификатор категорий расходов (ML)
                 ─► проверки ревизора (правила + подбор подмножеств)
                 ─► уточняющие вопросы ─► чеки/документы (OCR) ─► сверка по сумме
                 ─► итоговый отчёт (Markdown)
```

| Блок | Что делает | Где |
|---|---|---|
| CV | наклон скана (проекция), горизонтальные/вертикальные линии таблицы (OpenCV) | `osi/ingest.py` |
| OCR | EasyOCR для сканов и чеков, `pdfplumber` для PDF с текстом | `osi/ingest.py`, `osi/receipts.py` |
| Таблица | сборка строк, колонок «план/факт», починка OCR-ошибок в номерах и суммах | `osi/layout.py`, `osi/report.py`, `osi/amounts.py` |
| ML | классификатор категорий расходов (20 классов), сравнение 4 моделей | `osi/classifier.py` |
| Проверки | суммы по иерархии, остатки между месяцами, план/факт, скачки, смена ТОО↔ИП, двойные платежи, необычные статьи | `osi/checks.py` |
| Вопросы и отчёт | выбор документов для запроса, закрытие вопросов по сумме чека | `osi/analyze.py` |
| Данные | генератор синтетических отчётов с внедрёнными нарушениями + PDF-рендер | `osi/synth.py`, `make_samples.py` |
| UI | Streamlit-мастер из 4 шагов | `app.py` |

## Данные

* **Реальные документы** (3 месячных скана ОСИ, годовой отчёт, смета) — использованы
  для разработки парсера и для проверки «нет ложных нарушений». В репозиторий **не
  включены** (подписи, печати); папки `data/private/`, сканы и изображения в `.gitignore`.
* **Синтетические отчёты** — серии из 3 месяцев по реальной форме (Приложение к приказу
  № 164): согласованные суммы и остатки + внедрённые нарушения с известной разметкой.
  Отчёты рендерятся в PDF, поэтому проверяется весь путь «файл → парсер → проверки».
* **`data/real_lines.csv`** — 58 строк расходов из реальных отчётов, размечены вручную по
  20 категориям (тестовый набор классификатора; только текст назначения, без личных данных).
* Демо-файлы `data/samples/*.pdf` — вымышленные (`python make_samples.py`).

## Результаты

**Проверки на синтетических сериях** (300 серий × 3 месяца, у каждой нарушения с вероятностью 0.3):

| Нарушение | Precision | Recall |
|---|---|---|
| сумма строки ≠ сумме частей | 1.00 | 1.00 |
| остаток накопительного счёта | 1.00 | 1.00 |
| остаток текущего счёта | 1.00 | 1.00 |
| скачок суммы по статье | 1.00 | 0.99 |
| смена формы контрагента (ТОО↔ИП) | 1.00 | 1.00 |
| необычная статья (страхование жизни) | 1.00 | 1.00 |
| двойной платёж | 1.00 | 1.00 |

Сквозной тест (генератор → PDF → парсер → проверки, 30 серий): те же значения (`docs/metrics_checks_pdf.json`).
Важно: это правила, настроенные на тот же класс ошибок, который внедрён синтетически, поэтому
цифры — **верхняя оценка**; на реальных документах оценка — отсутствие ложных срабатываний
по арифметике и находка реальных аномалий (ниже).

**Реальные документы (3 месяца + год).** Арифметика и остатки сошлись (ложных нарушений нет:
остаток накопительного счёта = предыдущий + взносы 6.3; текущего = предыдущий + поступления −
накопления − расходы; годовой баланс с депозитом сходится до копейки). Найдено для проверки:
рост по комплексному обслуживанию (2,0 → 5,6 млн ₸), контрагент «ТКМ-Сервис» то ТОО, то ИП,
страхование жизни (85 000 ₸), отклонения от плана по налогам (+38%) и взысканию долгов (+459%),
депозит 21 млн ₸.

**Классификатор статей** (`docs/metrics_classifier.json`): обучение на синтетических
формулировках, тест — 58 реальных строк.

| Модель | macro-F1, отложенные фразы (синт.) | macro-F1, реальные строки |
|---|---|---|
| TF-IDF (символы) + LogReg | 0.41 | 0.91 |
| TF-IDF (символы) + LinearSVC | 0.41 | 0.91 |
| TF-IDF (слова) + LogReg | 0.33 | 0.90 |
| TF-IDF (слова) + ComplementNB | 0.33 | 0.89 |

Низкие цифры на отложенных синтетических фразах — задача жёсткая (в классе мало формулировок,
новые фразы не пересекаются по словам). Реальные строки лучше, потому что словарь категорий
составлен по терминологии отчётов — это надо учитывать при интерпретации (возможна оптимистичность).
Сравнение с мультиязычными эмбеддингами реализовано (`embedding_model()`, `compare(with_embeddings=True)`),
но требует доступа к Hugging Face — запускается в Colab/Space.

Графики: `docs/*.png` (EDA, матрица ошибок, сравнение моделей, метрики проверок).

## Ограничения

* Парсер рассчитан на форму отчёта из приказа № 164 (месячный и годовой отчёты); смета и договоры
  пока не разбираются, банковские выписки — только CSV/XLSX и только как подтверждение суммы.
* Качество на сканах зависит от OCR: перекос до ±3°, плохие фото могут давать пропуски сумм.
  Неуверенные места лучше проверять глазами.
* Замечания — это **подсказки** для ревизионной комиссии, а не юридический вывод.
* Чеки сверяются по сумме (допуск 1 ₸) и названию продавца; частичные оплаты не учитываются.

## Запуск

```bash
pip install -r requirements.txt            # лёгкая версия: текстовые PDF, без OCR
pip install -r requirements-ocr.txt        # по желанию: OCR сканов и фото (easyocr)
python -m osi.classifier        # обучение классификатора + метрики
python make_samples.py          # демо-файлы
streamlit run app.py
python -m pytest -q tests       # тесты
python -m pycodestyle osi app.py make_samples.py tests   # PEP8
python -m osi.evaluate          # оценка проверок на синтетике
```

### Streamlit Community Cloud (бесплатно)

Repository → share.streamlit.io → Create app → `app.py`. Устанавливается лёгкая версия
(`requirements.txt`): текстовые PDF и демо работают, сканы и фото требуют OCR
(`requirements-ocr.txt`, Docker или локальный запуск).

### Docker / Hugging Face Space

Space типа **Docker** (в этом README уже есть нужная шапка `sdk: docker`, `app_port: 8501`).
`Dockerfile` ставит CPU-версию torch, скачивает веса EasyOCR при сборке и обучает
классификатор. Первая загрузка скана на CPU занимает ~1 мин на страницу.

## Приватность

Загруженные файлы обрабатываются во временной папке и не сохраняются. История проверок —
по желанию пользователя (по умолчанию выключена): сохраняются только выводы, без файлов;
есть кнопка «Удалить историю». В публичный Space не загружайте реальные документы с
персональными данными.
